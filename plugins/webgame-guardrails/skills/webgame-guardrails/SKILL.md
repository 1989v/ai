# 웹게임 품질 가드레일

브라우저 게임을 만들 때 **완성 판정에 쓰는 게이트 모음**이다. 플랫폼에 묶이지 않는다 —
캔버스든 Unity WebGL 이든, 어떤 배포 구조든 적용된다.

전부 **실제로 반려당한 뒤에 생긴 규칙**이다. 각 항목에 그렇게 만든 사건이 함께 적혀 있고,
근거 없이 생긴 조항은 없다.

## 언제 읽나

| 상황 | 읽을 것 |
|---|---|
| 게임을 새로 만든다 | `references/guardrails.md` 전체 → 장르가 정해지면 `references/presets.md` 의 **해당 블록만** |
| 완성 판정 / 검수 | `references/guardrails.md` 의 G1-2 · G5 · G6 · G7 |
| "왜 이 게임이 모바일에서 이상한가" | G5 (모바일) · G1-2 (화면 축척) |
| "폰이 뜨겁다" | G7 (프레임 예산) |

프리셋 945줄을 통째로 읽지 마라. **게임 하나가 쓰는 것은 한 블록(40~60줄)**이다.

## 게이트 요약

| | 무엇을 막나 |
|---|---|
| **G1-2 화면 축척** | 벤치마크보다 캐릭터를 크게 만들어 맵이 좁아 보이는 것. 시야 폭 · 주인공 화면 비율 1/N · CSS px 세 수치를 **재서** 적는다 |
| **G1-3 벤치마크 일치도 심사** | 회차를 거듭할수록 원작 요소가 조용히 빠지는 것. **깨끗한 서브에이전트**가 소스만 보고 누락을 보고한다 — 만든 사람은 없는 것을 못 본다 |
| **G2 한국어 명명** | 직역투 UI |
| **G3 화면 흔들림** | 눈이 아픈 연출 |
| **G4 어중간한 3D** | 2D 도 3D 도 아닌 것 |
| **G5 모바일** | 이 프로젝트에서 **가장 자주 실패한 축**. 조작 대상 44 CSS px, 판별 가능 16 px 등 하한 |
| **G6 벤치마크 규모** | 맵 범위·해상도·플레이타임·진행 깊이. 품질과 **따로** 판정한다 — 예쁘지만 30분이면 끝나는 것을 막는다 |
| **G7 프레임 예산·발열** | 폰에서 픽셀 수 × 포스트 패스 × MSAA 가 곱해지는 것. 화질보다 온도가 먼저 온다 |

## 쓰는 법

1. **벤치마크를 먼저 정한다.** 그 작품의 맵 범위·해상도·플레이타임·진행 깊이를 수치로 적는다.
   "그 장르 최고작 정도" 는 규모를 말해 주지 않는다 (G6).
2. 장르 프리셋 블록을 프롬프트에 붙인다.
3. 만든다.
4. **완성 판정**: 화면 축척 세 수치를 재고, 폰 두 방향을 실측하고, 발열을 확인하고,
   깨끗한 서브에이전트에게 벤치마크 대비 누락을 받는다.

## 규율

- **게이트가 막으면 다시 만든다.** 임계값을 낮춰 통과시키지 않는다. 같은 방법으로 다시
  굴려서 통과시키지도 않는다 — 두 번 실패하면 접근을 바꿀 자리다.
- **예외는 이름을 불러 선언하고**, 다른 게이트가 전부 녹색일 때만 쓰고, 그 건에만 적용한다.
  그리고 **그 예외가 여전히 사 주지 않는 것**을 함께 적는다.
- **새 검사를 넣으면 적발 건을 열어 보고 참 양성인지 먼저 확인한다.** 규칙이 시끄러우면
  게임이 아니라 규칙을 고친다. 시끄러운 게이트는 곧 무시되는 게이트다.
- **눈으로 본 것을 근거로 삼지 않는다.** 값을 찍어서 확인한다.

## 이 문서의 성격

운영 중인 비공개 파이프라인(캔버스 게임 74종 + Unity WebGL 1종)에서 **플랫폼 의존을 걷어낸
사본**이다. 원본은 배포·랭킹·세이브 같은 자체 인프라와 엮여 있어 그대로는 남의 레포에서 못 돈다.

여기 남은 것은 **어느 웹게임에나 적용되는 판정 기준과 수치 규격**이다. 원본이 계속 바뀌므로
이 사본은 그 시점의 스냅샷이고, 자동으로 동기화되지 않는다.
