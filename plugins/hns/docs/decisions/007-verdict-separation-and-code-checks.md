# ADR-007: 발견/판정 분리 · 흉터 목록 · 코드화 계약

**Date**: 2026-09-07 · **Status**: Accepted · **Version**: 0.16.0

## Context
`myrealtrip/dev-all-ai-assistant-v2`(크로스플랫폼 6레포 오케스트레이터, 스킬 29·훅 8·에이전트 8) 벤치마크 —
보고서 `docs/benchmarks/2026-09-07-dev-all-ai-assistant-v2.md`.

파이프라인 뼈대(요구사항 → 계획 → 검수 → 승인 → 구현 → 검증)와 결정화된 자기완결 step 은 이미 hns 에 있다
(Step 모드가 같은 계보 — ADR/벤치마크 2026-06-04). **없던 것은 세 축**이었다.

1. **판정 주체가 분리돼 있지 않다.** `spec-review` 는 리뷰어가 발견과 판정을 겸하고, 강등 규칙("이중 근거 없는 BLOCK 은 REVISE")을 집계하는 메인이 적용한다. 구현 후 리뷰(`agent-behavior` §4)도 fresh 에이전트 하나가 둘 다 한다. 그런데 그 메인은 곧 구현을 지휘할 당사자다.
2. **사고가 코드 레벨로 누적되지 않는다.** `/hns:evolve` 는 실패를 memory/rules/hook/CLAUDE.md/스킬/스펙 리뷰어 체크리스트로 보내지만, **구현 프롬프트로 되돌아오는 경로가 없다.** implementer 는 "컨벤션을 따르라" 는 지시만 받고, 이 프로젝트에서 실제로 뭐가 터졌는지는 모른다.
3. **산문을 코드로 옮길 때의 계약이 없다.** evolve 표는 규칙이 *어느 파일로* 가는지만 정하고, 그 코드가 정본인지 미러인지·폴백이 있는지·열쇠가 몇 개인지는 정하지 않는다. 그리고 **막을 수 없는 규칙을 금지문으로 쓰면** 안 지킨 사실까지 안 보이게 된다(벤치마크 사고 #13: "시안 없으면 dispatch 금지" 가 강제 장치 없이 석 달 — step 파일 503개 중 준수 9개).

## Decision
1. **`hns:review-verdict` 에이전트 신설.** 리뷰어는 발견만 하고, 유지/강등/기각은 이 에이전트가 판정한다. **기각·강등은 실측 반증이 있을 때만**(표준에 수용된 패턴으로 명시 / 같은 레포에 동일 패턴 실존 grep / 인용 `file:line` 이 사실과 다름). 애매하면 유지. 메인은 판정을 재량 없이 따른다. `spec-review` 3단계와 `agent-behavior` §4 가 호출한다.
   근거: 부실한 수정은 다음 라운드가 재검출하지만 **기각은 같은 재량이 반복 적용**되어, 라운드 루프가 구조적으로 못 잡는다.
2. **서브에이전트를 못 부르면 메인이 대신 리뷰하지 않는다** — 멈추고 알린다. 저자가 검증자를 겸하면 그 단계는 존재 이유가 없다.
3. **흉터 목록 `docs/checks/`** — `common.md` + `{module}.md`. **두 시점이 같은 파일을 본다**: implementer 가 코딩 전 자기대조로(절차 2-b), 리뷰가 위반 관점의 사냥 영역으로(`review-protocol` Stage 3). 입구는 `/hns:code-check` 하나 — fresh 심판(판단 기울기 **관대**) → 행선지 → 중복 확인 → 출처 필수 → soft cap 140줄.
   컨벤션(`docs/conventions/`, "이렇게 쓴다")과 분리한 이유: 흉터는 append-only·출처 보존·분량 상한·주입 대상이라 규범과 수명·형식·독자가 다르다.
4. **리뷰어 발견 규율 3줄**(`review-protocol` Finding Discipline): Critical 전에 같은 모듈 기존 패턴 grep(있으면 한 단계 강등 + 근거) · 일반론 금지(이번 변경의 의도와 어떻게 닿는지 한 줄) · 스타일 금지.
5. **코드화 계약 3분류**(`evolve`): **조언**(산문이 정본, 실패 시 폴백, 판정을 사용자에게 보임) / **형식 쓰기**(엄격하되 모르는 값은 보존) / **자물쇠**(막되 열쇠 정확히 하나). 조언만 산문을 남긴다.
6. **막을 수 없으면 금지하지 말고 드러낸다**(`evolve`). 빨간불을 만들 수 없는 규칙은 금지문이 아니라 **표기 의무**로 — 통과시키되 어긴 사실이 산출물에 남게.
7. **빼기 규칙 둘**(`evolve` 절차 2·3): 예외 경로에서 나온 실패는 규칙 추가 전에 **그 경로의 범위 축소**를 먼저 본다 · 새 단계·플래그는 **네 시점(만들 때·끝날 때·중단할 때·복귀할 때)** 을 한 번에 정의한다.
8. **`commit-scope.sh` 훅.** 커밋에 담기는 범위를 드러내고, **차단은 하나** — 스테이지된 서브모듈 포인터가 HEAD 기록보다 뒤로 갈 때(enforce). 미푸시 포인터·빌드산출물/자격증명 경로·`-a` 커밋은 알림만. 6 → 5 를 그대로 적용한 것: "이번 작업과 무관한 변경" 은 기계가 판정할 수 없으므로 막지 않고 드러낸다.

## Consequences
**+** 리뷰 발견이 구현 당사자의 재량으로 사라지지 않는다. 한 번 터진 결함이 다음 구현의 입력이 된다(evolve 가 못 채우던 자리). 규칙을 코드로 옮길 때 정본이 하나로 정해진다.
**−** 리뷰 라운드마다 에이전트가 1회 늘어난다(발견 0건이면 생략). `docs/checks/` 는 방치하면 늘어나기만 하므로 cap·삭제 규약과 `/hns:diet` 이 균형추다. 흉터 목록이 없는 프로젝트에서는 3·4 가 무동작(정상).

## Not adopted
work-order + 외부 `execute.py` 커널(Step 모드로 이미 흡수 — 상태 소유권이 둘로 갈린다) ·
`next-step.py` 순회 조언자(슬라이스×레포 이중 루프의 산물, hns 는 단일 축이라 조기 최적화 — **분류 체계만** 가져왔다) ·
`current.md`/`ticket.md`/`slices.md` 4파일 상태 모델과 `progress.py`(멀티 레포 × 멀티 세션의 산물) ·
소통 모드(개발자/비개발자) · Jira 라이프사이클 · repo-registry/context 산출물 · 크로스레포 순차 실행(조직 구조 대응물) ·
handoff 파일 · 규모 축소 레인(quick-fix) · 하네스 자기 변경 검토 + 시뮬 3렌즈 — **후속 후보**(보고서 「조건부」).
